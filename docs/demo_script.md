# 课堂演示脚本（目标7分30秒）

本脚本是可复现演练材料，尚未代替小组实际录屏。建议先跑无网络版本，再展示保存的真实模型结果；原始作业接受课堂Live Demo或不超过8分钟录屏。

## 准备

在仓库根使用项目Python，先完成依赖安装，执行：

```powershell
.\.venv\Scripts\python.exe -m scripts.demo_prd
.\.venv\Scripts\python.exe -m pytest -q
```

第一条命令使用七个真实架构实现、group_02仿真资料、显式模型替身与演示审核决定，无网络、无支付。M5替身来自测试夹具，不能把该输出称为真实营销模型效果。控制台展示M2两轮动作与观察、M7反思节点和回滚；完整快照写入 `tests/artifacts/prd_demo.json`。第二条命令默认跳过付费测试。

## 时间安排

| 时间 | 演示内容 | 要讲清的区别 |
|---|---|---|
| 0:00–0:45 | 展示架构图与七模块目录 | 七种控制流独立；平台选择模块，M4选择Skill |
| 0:45–1:30 | M1双工具/记忆，M4知识库来源与冲突 | 无资料不编政策；闲聊不等于检索错误；第5个Skill扩展测试 |
| 1:30–2:30 | 展示M2的decision_summary、action、result和stop_reason | 决策摘要是公开轨迹，不是模型隐藏推理；程序固定订单号 |
| 2:30–3:45 | W40/W41两次M6融合→M3环比→M5四角色 | 黑板更新触发、计划与执行分离、角色通信和汇总；-8.91%可核算 |

## 现场交互审批

同一进程启动 `python -m hub_platform --chat --real-m2 --real-m7 --real-m1`，模型与HUB_DATA_DIR按本机环境配置。先输入“查询订单2025100004，再按实际订单金额申请整单退款，原因是买错了”。查看实际等待步骤ID后提交：

```text
/review {"step_id":"s2","approved":true,"reviewer":"现场审核员","material_complete":false}
/review {"step_id":"s2","approved":true,"reviewer":"现场审核员","material_complete":true}
```

步骤ID以实际计划为准，不假设总是s2。要直接演示确定的下游续跑，使用无网络脚本里的三步骤退款计划。上述决定属于演示；实际使用应由审核人员根据材料明确选择，模型不会代为同意。拒绝用 `approved:false`，结果为已完成的“驳回”，不触发打款。`/new`后可带原task_id审核历史等待任务，退出程序后不可恢复。
