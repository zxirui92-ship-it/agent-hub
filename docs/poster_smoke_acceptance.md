# 2026-10-16 海报路由修复验收

## 后续：提示词模块与 Image 2.1

用户提供实际成图后发现：旧提示词将事实限制等说明直接传给图片模型，导致密集正文、标题乱码。前次“返回图片资源”的验收不足以证明海报可用。

新增独立 `ImagePromptWriter`：文字模型撰写视觉设计，程序锁定经营文案，校验通过后 `PromptedImageSkill` 才调用图片服务。经营事实与校验规则不再作为长篇海报正文。网页提供可展开的设计说明、画面文案和实际提示词。

图片默认切换为 `qwen-image-2.1-pro`，撰写模型沿用项目文字配置（当前 `qwen-plus`），超时默认 600 秒。
本地回归：1455 passed / 39 skipped；前端 15 passed。首次全量测试因旧 pytest 临时目录权限失败，使用新的项目内 basetemp 后全量通过，未删除旧目录。

真实验证脚本扩展至 12 种问法，其中仅一次实际出图，新增 4 项仅调用文字模型检查提示词。当前真实验证待授权；不能将配置生效等同于远端模型可用或视觉验收通过。

## 现场证据

用户原话：“就2025w43的运营情况，帮我生成一份双十一的成果海报”。

后续规划器没有把这些数值传入 M4，而是自行添加“使用 Markdown 格式输出”。M4 因此选择 code_gen，输出未经数据支持的 4.12 亿元等内容。

## 修复与验证范围

- M4 1.1 增加 output_kind 和 fused_data；图片请求只允许图片工具，文本不能冒充图片资源。
- 规划器保留用户原始图片目标，校验明确周次的经营海报数据来自已完成 M6 历史结果或本计划同周 M6 引用。
- 图片提示词传入原始指标、程序计算的 ISO 周日期及来源限制；前端同时显示图片和使用的指标。
- 成功的 M4 路由也写入 stderr 日志，包括工具、交付类型、数据周次和关联 ID。
- 回放原错误计划、错误路由、遗漏/伪造数据等本地测试均通过。全量 Python 回归 1450 passed / 39 skipped；随后对最后的边界调整运行相关 91 项，全部通过。前端 14 项通过。
